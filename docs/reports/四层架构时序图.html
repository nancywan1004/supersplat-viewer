四层架构时序图

必须区分四层：职责不同、耗时归属不同、优化杠杆不同。Poland 慢帧瓶颈在引擎·CPU（gapMs），不是 Viewer tick，也不是 GPU 绘制。

V = Viewer refinement N = PlayCanvas native V+N = Viewer 调度 + 引擎执行
为什么要分四层？ 混在一起会误判瓶颈：scan 只要 1ms 却和 bake 120ms 归为一类；网络下载跨帧却和单帧 gap 混淆；writeBuffer 是 CPU 发起但数据落 GPU。四层对齐后，profiler 指标才能对上号。

⑪–⑭ Bake 四步 · 是什么？

flowchart LR
  s11["⑪ applyLodChanges\nB层 intervals"]
  s12["⑫ Allocator\nMemBlock 订座"]
  s13["⑬ assign + staging\n索引 + CPU 拷数据"]
  s14["⑭ writeBuffer\n→ Work Buffer"]
  s11 --> s12 --> s13 --> s14
步骤层粒度做什么时序#
applyLodChangesB 逻辑层叶/块按 optimalLod 改 currentLod；更新 filePlacements.intervals（读 SOG 哪段）⑪
AllocatorC 物理层MemBlockfree 旧段 + allocate 新 size → _allocationMap[allocId]={offset,size}⑫
assignSplatOffsetsC 物理层splat读 MemBlock.offset → intervalOffsets[]；needsUploadIds.add(allocId)⑬
stagingC 物理层字节CPU 从 SOG Resource 读 position/rot/scale/color 写入临时缓冲⑬
#步骤一句话
⑪applyLodChanges换菜单：改读哪段 SOG
⑫Allocator订座：WB 里划 slot 段
⑬aassignSplatOffsets点名：每 splat 索引 + dirty 标记
⑬bstaging备菜：SOG → CPU 缓冲
⑭writeBuffer上菜：CPU → GPU Work Buffer
和 Allocator 的区别 Allocator 按块订 WB 座位（⑫）；assignSplatOffsets 按splat建索引（⑬a）；staging 按字节拷 SOG 属性（⑬b）。Poland gapMs 主要在 ⑬，不是 ⑫。

参数值何时生效
