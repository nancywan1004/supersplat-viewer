实体与字段

展开 · A / B / C 三层
层核心对象干什么用换档时
A · 资产层SOG Resource（GPU 纹理）每个 SOG 文件的「原材料库」：下载解码后的扁平 splat 数组 [0..numSplats)。在答两件事——① 源 splat 在 GPU 哪；② bake 从哪段采样（段范围由 B 层 intervals 指定，Resource 本身不被改写）换档不改 Resource 内容；只改 B 层「读哪一段」
B · 逻辑层NodeInfo + GSplatPlacement决定「哪片空间叶、用哪档 LOD、哪份 SOG 被哪些叶引用、各读源文件哪一段」。NodeInfo 管每叶的 allocId / currentLod；Placement 管每个 file 的 intervals Map。Viewer/引擎换档主要改这一层applyLodChanges 改 intervals / currentLod → 触发 WorldState 新版本 + bake
C · 物理层_workBuffer + MemBlock（_allocationMap）GPU 真正拿来 draw 的大 splat 数组，加上「货架台账」（每个 allocId 占 WB 哪段 slot、多大）。在答两件事——① 这叶最终写到 WB 哪；② 本帧哪些 slot 要重烤（needsUploadIds 过滤 partial bake）Allocator 调整 offset/size；bake 把 A 层片段 copy 覆写到 dirty 块
展开 · 核心实体职责
实体数量级层核心职责
SOG Resource每 SOG 文件一个A · 资产层HTTP fetch 解码后的 GPU splat 纹理，扁平数组 [0..numSplats)。换档只改「读哪段」，不改 Resource 内容；GSplatPlacement.resource 持有其引用，bake 按 GSplatInfo.intervals[] 从中采样
GSplatOctreeInstance每个 Entity 一个B · 场景运行时每个可见 Entity 的 octree 入口：nodeInfos[]（每叶 LOD/allocId）+ filePlacements[]（按 fileIndex 索引的 Placement）。applyLodChanges 在此写 intervals；inst.update 驱动 GSplatWorld 构造 WorldState 并 bake
GSplatPlacement每份 SOG 文件一个B · 文件→叶映射一份 SOG 的可变运行时记录：resource→A 层；intervals Map<nodeIndex,[start,end)> 记录哪些叶正用此文件、各读源数组哪段。换档只改 Map；多叶可共享同一 placement（N 叶 → 1 placement）
NodeInfo每个空间叶一个B · 叶级 LOD每片 octree 空间叶：currentLod（屏上档）、optimalLod（理想档）、allocId（构造时一次分配，终身不变）。换档改 currentLod 与所用 file，不重新 get allocId
GSplatWorld整场景共享一个B+C 枢纽跨帧持久的世界管理器：BlockAllocator、_allocationMap、_workBuffer、_worldStates（Map<version, State>）。所有 Instance 共用同一 allocator 与 WB；placement 变时 _updateWorldState 生成新版本并触发 assign/bake
GSplatWorldStateplacement 变一版C · 版本快照某一版「本帧要上屏」的总清单（容器）。splats[] 即 GSplatInfo[]：每条对应一份 active GSplatPlacement（≈本帧用到的 SOG 文件数，不是 node 数、不是 splat 点数）。needsUpload[]⊆splats[] 为本帧要 bake 的子集；needsUploadIds（在 State 上）标 dirty 的 allocId；totalActiveSplats=Σ interval 长度→HUD gsplats
GSplatInfosplats[] 里每条 ≈ 一个 active fileB→C 桥 · 快照WorldState.splats[] 的元素：从 GSplatPlacement 快照的只读本版合同（new GSplatInfo(placement)）。一条可含多 interval（同 SOG 多叶→1 条 Info，intervals[] 多段）。assign 后填 intervalOffsets[]（WB 目标）；bake 按 intervals+offsets+resource 把 A 层拷进 C 层 slot
BlockAllocator + MemBlock持久C · 订座在 work buffer 地址空间为 allocId 划连续 slot 段 {offset,size}。换档常只改 block 的 size/offset；grow/defrag 时才整池重排并可能触发 fullRebuild
_allocationMap持久 MapC · 账本allocId→MemBlock，跨 WorldState 版本存活。assign 写入/更新；rebuildWorkBuffer 用 needsUploadIds 过滤本帧要 overwrite 哪些 id；叶下屏或换档释放时 free + map.delete

展开 · 核心字段速查
字段/对象层干什么用换档 / 本帧时
GSplatWorld._allocationMap / _workBuffer持久 · C 物理层_allocationMap：「货架台账」——每个 allocId 在 WorkBuffer 里占哪段 slot、多大。_workBuffer：GPU 真正 draw 用的大 splat 数组，所有上屏数据最终都烤进这里对象跨版本存活；换档只改台账里的 offset/size，再 partial bake 覆写对应 slot
GSplatWorldState.splats[]版本快照 · 每帧一版本版「上屏清单」：哪些 SOG file 在屏、每 file 哪些叶 active、各读 SOG 哪段、写到 WB 哪段——全部拍成 GSplatInfo[]，供 bake 与渲染只读消费placement 集合一变（增删 file、改 intervals）→ version++，生成新一版快照
GSplatWorldState.needsUploadIds版本快照 · 本帧 dirty 清单增量 bake 的「待办」：本帧只需重烤哪些 allocId 对应的 WB 块；不在 Set 里的 slot 本帧可跳过 copy，省 CPUassignSplatOffsets 构造 WorldState 时填充；字段在 WorldState 上，不在单条 GSplatInfo 里
GSplatInfo.intervals[] / intervalOffsets[]快照 · B→C 桥梁intervals：每个 active 叶在 SOG 源文件里读 splat 的半开区间 [start,end)。intervalOffsets：读到的数据写到 _workBuffer 哪个 slot 起点。bake 只认这两列，从 Resource 采样再写入 WB换档改 placement → 新 WorldState 重算两数组；bake 按新合同覆写
NodeInfo.allocId / currentLodB 层 · 八叉树每空间叶allocId：该叶 WB 空间的永久身份证，加载时 GsplatAllocId.get() 发一次。currentLod：这叶当前实际上屏的 LOD 档（ladder 第几级；-1=下屏）换档改 currentLod 和 placement.intervals，allocId 不变；下屏后 allocId 才可能被回收释放
GSplatPlacement.intervalsB 层 · 每个 SOG file 一份living 表：「这个 file 里哪些空间叶在上屏、各自用 SOG 里哪一段 splat」——Map<nodeIndex, [start,end)>，引擎 apply 的直接写入点applyLodChanges 据 optimalLod 增删/改条目 → 触发 _updateWorldState → 新 splats[] 快照与 bake

三个关键结论

① allocId 终身不变，变 MemBlock offset/size。② needsUploadIds 在 WorldState。③ fetch 与 apply+bake 跨帧分开。

管线 A vs B

sync/inst.update 各 1 次相同；差异在 needsUploadIds 规模：{101} vs ≈26 → gapMs≈119ms。

Native vs Refinement

一句话

bake 链相同。差在换档请求如何进入 applyLodChanges：Native 按 file 落地节拍摊平 vs Refinement 高并发先囤、burst 末一次 sync 打包。

故事设定（下列对照共用）

同一次相机移动：视锥里突然需要 10 个新 fine LOD 文件。Native 并发=2；Refinement burst 期并发≈6。只比 unlock 之后的稳态（两边首屏 bootstrap 已共用）。每帧公共骨架：输入 → update（调度）→ framerender（引擎 streaming）→ frame:ready → render / bake / GPU → frameend。

needsLodSwitch 只在 Refinement

Native unlock 后 Viewer 不算 needsLodSwitch。Refinement scan：currentLod > targetLod（该升档）或 currentLod < 0（未上屏）→ true；currentLod ≤ targetLod 直接 OK（不为降档 sync）。apply 仍听 optimalLod。

F2–F3继续「落地 1～2 个 → apply 一点 → 再拉下一批」。换档均匀洒在多帧。loadingCount 台阶式下降。burst 窗口内反复 scan / 排队 / boost。file 快速囤齐；staleLoaded 堆高。偶尔 cooldown sync，或等 burst_lod_switch 打包。

记法
