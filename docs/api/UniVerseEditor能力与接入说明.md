# UniVerse Editor 编辑能力与接入说明

更新日期：2026-10-20。

本文面向通过 UniVerse Studio SDK 在网页中接入场景编辑的客户，说明 Editor 的模型、相机轨道编辑能力及使用边界。三维重建 REST API、完整场景浏览和客户存储接口分别以对应文档为准。

## 1. 统一通过 Studio SDK 接入

客户网页接入 Studio SDK，由 Studio 管理 Viewer，并在需要编辑高斯模型或相机轨道时打开 Editor。Editor 提供完整编辑界面，编辑结果交回 Studio。

- 客户使用同一套 Studio SDK，不需要再引入或初始化第二套 Editor SDK。
- SDK 包提供 `studio-sdk.js`（ESM）、`studio-sdk.global.js`（普通 script 标签）和 TypeScript 类型声明；加载、保存及退出方法见 Studio SDK 使用说明。
- 场景资产、标注、环境、特效、滤镜和天空盒等完整场景能力由 Studio 与 Viewer 协同提供，不是 Editor 单独提供的八个接口。
- Editor 的可信直接父容器是 Studio，而不是最外层客户网页。当前托管服务只接受其配置的 Studio 来源消息；不能把 Editor 地址当作任意网页可直接使用的独立嵌入接口。
- 普通 SDK 接入无需客户为 Editor 单独配置可信来源。需要改变托管关系时，应由服务提供方确认配套接入方式，不能通过修改 URL 参数绕过来源校验。

## 2. 托管地址

| 用途                 | 地址                                                                     |
| -------------------- | ------------------------------------------------------------------------ |
| Studio 统一接入地址  | [UniVerse Studio](https://universe-api.bdnrc.org.cn/)                    |
| 在线接入示例         | [Studio SDK Demo](https://universe-apidemo.bdnrc.org.cn/demo/index.html) |
| 正式 Editor API 入口 | [正式 Editor](https://3dgs_editor.bdnrc.org.cn/?editorRuntime=api)       |
| 测试 Editor API 入口 | [测试 Editor](https://3dgs_editor-dev.bdnrc.org.cn/?editorRuntime=api)   |

Editor 地址由 Studio 配套使用，不是客户 SDK 的初始化地址。直接打开 Editor API 页面时，没有 Studio 编辑会话，仍可使用本地导入、下载等入口，但不能通过“完成”把结果提交给不存在的宿主。未指定 `editorRuntime=api` 的默认入口使用原编辑模式，不能与 API 接入方式混用。

## 3. 模型与相机轨道能力

### 高斯模型编辑

- 提供模型选择、裁剪、删除、变换等编辑操作，具体入口以当前编辑界面为准。
- 只编辑模型时，不要求场景已有相机轨道，也不会因此获得修改相机轨道的权限。
- 完成时将模型变更交回 Studio；未变更的模型可返回未修改标记，不重复输出模型文件。

### 相机轨道编辑（v2）

- 可以编辑已有目标轨道，也可通过新增关键帧创建新轨道；零轨道场景不影响模型编辑。
- 已有目标按原始轨道数组位置定位，不依赖轨道名称唯一；未选中的轨道和其他配置字段保持不变。
- 单次编辑会话最多返回一项轨道新增、替换或删除；路径编辑可以同时交回模型变更。
- 支持当前解析器可识别的 `step`、`spline` 插值及正数帧率，不限于 30fps。不支持的插值、关键帧结构或通道修改会明确提示，不能仅凭“可加载配置”认定该轨道可编辑。
- 纯模型编辑不会静默丢弃意外产生的轨道修改；出现用途不一致时会提示错误。

## 4. 输入和输出格式

须区分 Studio 向 Editor 传入模型，以及用户在 Editor 内点击“导入本地模型”两种操作。

| 操作                      | 当前范围                                                                                                    |
| ------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Studio 向 Editor 传入模型 | 一个模型 `File` 或绝对 HTTP(S) URL；支持单文件 `.ply`、`.splat`、`.sog`、`.ksplat`、`.spz`                  |
| Editor 本地导入单文件模型 | 支持上述五类格式；PLY 必须包含可解析的高斯模型数据，不是任意点云 PLY                                        |
| Editor 本地导入资源组合   | 支持 SOG 的 `meta.json` 与配套文件，或 LCC 的 `.lcc` 与配套文件；一次资源组合导入应选择一个完整模型及其依赖 |
| 模型修改回传、下载模型    | PLY，不承诺保持输入模型的压缩格式或文件大小                                                                 |
| 下载配置                  | 单独下载 `settings.json`，不是完整场景资源包                                                                |

- Editor 宿主协议当前不接收完整项目 ZIP、目录 `File[]` 或整套场景资源映射。`.ssproj`、相机 JSON 和 PLY 序列也不属于该宿主模型输入契约。
- Studio SDK 的普通本地模型、项目目录及 LOD 加载范围见 SDK 文档。项目 ZIP 需先解压并保留目录层级；这不等于 Editor 能直接编辑整个 LOD 目录或 `lod-meta.json`。
- 本地资源组合导入能力不等于宿主协议已支持同一组合。不要将 Editor 的五类格式或 LCC 导入范围直接当作 Studio SDK 的全部输入格式承诺。
- 完整 settings 中未编辑的字段会保留，但不表示 Editor 会恢复、渲染或打包其中全部媒体和场景资源。完整场景仍由 Studio 与 Viewer 管理。

## 5. 完成、取消、保存和下载

| 操作                            | 含义                                                                          |
| ------------------------------- | ----------------------------------------------------------------------------- |
| Editor“完成”                    | 生成编辑结果并交给 Studio，等待 Studio 确认应用；不自动执行客户上传或项目保存 |
| Editor“取消”                    | 取消本次编辑交接，未提交的修改不应用到 Studio 场景                            |
| Editor“下载 PLY／下载 settings” | 下载本地副本，不自动触发“完成”或 Studio 项目保存                              |
| Studio“保存”                    | 按 Studio SDK 的保存约定处理；未配置客户保存回调时生成项目 ZIP 并开始下载     |
| Studio 工具栏“下载”             | 下载项目 ZIP，不调用客户保存回调                                              |

推荐操作顺序：进入 Editor → 编辑 → 完成并确认已应用 → 返回 Studio → 保存。

交接失败或超时时会保留错误提示和可重试状态，不显示“已应用”。客户页面应按 SDK 的实际结果处理后续操作；销毁实例不会自动保存。

完成或取消后，Editor 仍可进行本地导入、下载和预览，但不能继续复用已结束的会话向 Studio 再次提交。重新进入宿主编辑需要新的编辑会话。

项目 ZIP 保留已有远程资源引用，不保证把所有远程素材下载到包内；Editor 下载的 PLY 和 settings 也不等于完整项目 ZIP。下载开始不等于文件已写入磁盘。

## 6. 资源访问与 CORS

跨域配置应设置在提供模型、配置及资源的文件服务器或 CDN 上，按实际读取来源授权：

- Studio 读取来源：`https://universe-api.bdnrc.org.cn`。
- 正式 Viewer 读取来源：`https://3dgs-viewer-api.bdnrc.org.cn`。
- 正式 Editor 读取来源：`https://3dgs_editor.bdnrc.org.cn`。
- 使用测试 Editor 时，相应文件还需允许 `https://3dgs_editor-dev.bdnrc.org.cn` 读取。其他测试组件按其实际部署来源配置。

仅允许 Studio 来源，不足以保证 Viewer 或 Editor 可以读取同一模型。配置文件、模型依赖和 LOD 分片等应分别满足其读取端的访问要求；允许 iframe 嵌入与资源 CORS 是不同事项。

- 模型 URL 应为有效的绝对 HTTP(S) 地址，不包含用户名／密码。需要访问鉴权时可使用有效签名 URL，不应假定 Editor 会自动附加客户业务请求头或 SDK Token。
- 保留原始 URL 及签名查询参数，不要统一解码中文路径或重写签名 URL。资源应返回实际文件及正确内容类型，不能以登录页或 HTML 错误页代替。
- 使用 HTTPS 或本机安全上下文。浏览器的本地网络访问、下载及文件选择限制按实际运行环境处理；本地导入不等于自动上传，也不承诺原位写回原文件。
- 本地预览仍会加载在线渲染库，因此不是离线安装包或完全离线交付。配置中的相对资源引用被保留，也不代表这些资源已在 Editor 中恢复。

## 7. 鉴权和客户存储职责

客户通过 Studio SDK 传入有效的原始 `accessToken`，不要将 `AccessSecret` 放入公开网页或前端构建产物。Token 的申请、刷新和有效期以后台 OpenAPI 文档及接口返回为准；Editor 不另提供一套申请或刷新接口，也不单独定义固定有效期。

SDK 不负责自动申请或刷新 Token。更新 Token、切换浏览／编辑模式时，按 SDK 使用说明销毁并重建实例，重建前处理未保存内容。浏览模式不提供 Editor 编辑和项目保存能力。

Editor 不直接管理客户上传、项目版本或持久化。客户保存服务、资产库及重建／计费接口的接入方式，分别以 Studio SDK 和后台服务文档为准；本指南不新增这些接口。

## 8. 高级接入说明

普通客户不需要自行发送 Editor 底层消息。当前 Studio 与 Editor 使用 `gs-editor` 消息通道，兼容协议 v1 和 v2；这里的协议版本不是 SDK 包版本或重建 REST API 文档版本。

v2 交接包含编辑用途和设置基线版本；仅相机轨道编辑指定明确的目标轨道，纯模型编辑不传目标轨道。结果按实际编辑内容返回模型变更及轨道变更。Studio 核对会话和基线后应用，并回传结果确认。来源校验、会话隔离、取消和迟到消息保护均应保留，不得将“收到结果”直接视为“已应用”或“已保存”。

需要脱离 Studio 自行管理 Editor 生命周期、改变输入输出契约或扩展格式时，应先确认配套接入契约；不要将当前托管地址、公开 URL 参数或底层消息片段包装成第二套通用 SDK。
