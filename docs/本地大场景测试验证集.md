2. 新增**lodRenderScale** \(参考Spark\)

    1. 目标：为了有效避免在视觉清晰度到位后仍拉取更细粒度的L0文件，减少调度压力

    2. 定义：屏幕像素阈值（默认1\.0），代表了每一叶当前档的代表 splat的尺寸，投到屏幕上至少要有多大（px）才算够清晰。

    3. 步骤

        1. 资产侧：离线计算每个叶子节点（chunk）的每个档位下的代表splat的世界尺寸**repScale**（取中位数）

            1. 对每个叶内的高斯点找到最长两个轴，并拿到最长两半轴长度a和b

            2. 找到以a和b为轴的椭圆对应的等效圆直径d

            3. 根据高斯点透明度做加权

            4. 再对所有 `(diameter_i, weight_i)` 做加权中位数 → p50中位数

            ```Plain Text
            diameter_i = 2 * sqrt(a_i * b_i)
                  weight_i   = 1 / (1 + exp(-opacity_i))
            ```

            

        2. 调度侧

            1. 计算每个叶子节点当前档位的代表splat投射到屏幕上的尺寸**screenDiameter**

                ```Plain Text
                // 在焦点处，1 米世界长度对应多少像素 ——由分辨率高度和垂直 FOV 决定
                pixelFactor = viewportHeight / (2 × tan(verticalFov / 2))
                
                // repDiamter: 叶×档的代表 splat 世界直径（米）（leafRepScale）
                // distance: 相机到该叶的距离（米）
                // 叶子节点当前档代表splat投到屏幕上有多大（px）
                screenDiameter = repDiameter × pixelFactor / distance
                ```

            2. 选档：拿屏上直径**screenDiameter**与（foveation后的）目标阈值**lodRenderScale**比较

                1. 计算每个节点的foveateFactor （中央接近1、边缘更粗\>1）

                2. 计算foveation后的effective阈值：`effective = lodRenderScale / foveateFactor`

                3. 找到第一个`screenDiameter[lod] >= effective` 的档作为renderScaleLod

                4. 计算targetLod：`targetLod = max(renderScaleLod, engineOptimalLod)`

                5. 写回 nodeInfo\.optimalLod，引擎底层根据此按需拉取新文件

    ```Plain Text
    估算：count(L) = pointCount × r^L
    默认管线 r = 0.5（fixed 50%）
    条件：count(N) < 96K 且 count(N-1) < 96K
    上限：N ≤ 12
    ```

    目的：最远两档各打成一个物理 SOG，远距加载几乎只拉一两个文件。

2. 分块：

    1. 96k、10米：96k为硬上限、\<96k的chunk继续按照10米为边长细分

    2. 新增**minChunkPoints**: 

        1. 目的：针对于大场景碎叶过多问题，有效控制总叶子节点数量（36万\-\>3万级）

        2. 限制chunk最小总点数为**2048**，只有大于此点数可以继续按照10米尺度来分

        3. 是否越粗越好：并非，过粗的chunk也会造成单次draw gpu耗时较高

        4. 实验：

        \[Poland\-CDN三方对比\.html\]

        

### **Viewer侧策略**：

1. 新增对于**lodBaseDistance**的**lodAlignScale：**

    1. 目的：针对小尺度高密度且叶子节点分布不均的场景，有效降低变清晰时长

    2. 第一步：计算场景稳健半径

    3. 第二步：计算远景目标档（场景在哪个档位时总点数降为原点数1/64、也就是0\.5倍降采样对应的LOD6）

    4. 第三步：反推 `原始基准 = 稳健半径 / 倍率^(目标档−1)`\(层级间倍率默认为3\)

    5. 第四步：最终**lodBaseDistance** =` clamp(原始基准 × 质量系数, 0.15, 配置值)`

        1. Quality: 1\.8 （更早拉L0、但会积压多个节点、变清晰慢）

        2. Balanced: 1\.4 （默认）

        3. Performance: 1\.0 （更晚拉L0、但会更快变清）
