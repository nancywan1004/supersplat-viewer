### 1) 视频导出：资产就绪聚合与时间轴语义（5.10）

- **问题**：主场景与子资产加载时点分散，导出起点与总长和「.anim 铺满、资产未齐」易打架；VFX 与 anim 同长时难再延长一圈；桥接预计算与执行层不一致；极速 MP4 保存类型与格式不一致。
- **目标**：导出启动前可等待「主场景 + sceneAssets + placement」就绪；时间轴在 syncAnimTrack 下同时满足 VFX、资产齐、整圈 anim；桥接与 `exportVideo` 同一套总长；MP4 保存名与 MIME 一致。
- **方法**：
  - 抽离 `asset-loader` 单例：按标签 `trackPromise` 聚合任务，对外 `waitAllReady`、就绪/超时事件，放置与 facade 侧统一接入。
  - `export-timeline-resolver` 用 `allAssetsReadyAt` 与 `extraAnimLoopsAfterAssetsReady` 等与 VFX 时长取大，消解「默认 12s 与 anim 同长则无法再播一圈」类边界；无 anim 时在资产齐后追加可配尾长。
  - `video-export` 启动前等待就绪并传入 resolver；`VIDEO_EXPORT_START` 预计算总长同样等待，与执行层对齐。
  - 极速导出保存分支按 MP4 修正 `showSaveFilePicker` 类型与建议扩展名。

### 2) 资产变换：镜像与四元数持久化（5.08）

- **问题**：`scale` 为负（镜像）叠加旋转后，保存重载偶发姿态不一致或单轴翻转错位。
- **目标**：镜像与缩放语义稳定；旋转以四元数为主、欧拉兼容旧数据；恢复顺序不产生等价解抖动。
- **方法**：
  - `transform` 使用 `scale` + `mirror`（每轴 ±1）表达镜像，与负 `scale` 混用收口。
  - 持久化增加 `rotationQuat`，写入时欧拉与四元数并存，读取优先四元数、旧数据回退欧拉。
  - 场景恢复顺序固定「先旋转（优先 quat）→ scale → mirror」，避免镜像参与旋转反解抖动。
  - 变更范围控制在资产 schemas/序列化/放置链路，不涉及光源／标注协议。

### 3) 资产放置防卡死与相机／拾取数值守护（4.29）

- **问题**：放置态异步等待过久时流程挂起，点击被长期 claim；切换资产并发时旧下载晚到覆盖新意图；双击聚焦链路遇非有限几何导致黑屏。
- **目标**：任一等待有超时失败与释放；后发请求胜出；双击／orbit／lerp／上屏全线拒绝 NaN／Inf。
- **方法**：
  - 实例化／`asset.loaded`/mesh hydrate 等待加统一超时，超时失败并解开放置链路；预下载增加超时与取消清理。
  - 放置请求版本号：新请求取消可取消的旧 mesh 下载，旧结果迟到不覆盖当前待放置项。
  - pick 与 `orbitFocus`、`Camera.look/lerp`、`applyCamera` 对非有限 `worldPoint`、距离与姿态做闸门，避免坏状态写入实体。

### 4) PBR 高反光与天空盒／IBL 职责拆分（4.28–4.29）

- **问题**：同资产在不同场景（主光配置差异）下 mesh 明暗不一；反射与天空背景强耦合导致「提亮天空却牵动反射」、初始偏亮后变暗等波动。
- **目标**：暗场景可读；背景显示与反射环境 atlas 分工清晰；夜景下天空可读且不过曝。
- **方法**：
  - 对高反光 Standard 材质检测 metalness／光泽／贴图等，按需抬 ambient、Diffuse、微调 metalness、弱 emissive，`useSkybox` 按需关闭以降低场景间.sky 差异。
  - 渲染侧保证高精度 HDR 通路，允许超过 1.0 的材质参数落到实处。
  - `applySkyboxTexture`：`skybox` 专司背景，`envAtlas` 使用独立纯色反射源；反射基线抬为亮白；NightMode 中 `targetSkyboxIntensity` 按夜景曲线重调，与高反材质链路叠加。

### 5) Reveal／VFX／growth-wave 与帧门控（4.27–4.28）

- **问题**：首帧上屏前偶发偏色／蓝光闪；growth-wave Phase1 远距点被裁切或与相机朝向相关的 far 不足；远景点过小；曾因 `forceRenderNextFrame` 与 `readyToRender` 顺序导致卡在 100% 的死锁回归。
- **目标**：NightMode 与 VFX、材质预热时序无争用；growth-wave 外推粒子在斜视下仍在 far 内；远距离点可读；按需渲染与预热帧相容。
- **方法**：
  - Reveal `createEffect` 与 Viewer 预热：延迟一帧或有限多帧 Shader 就绪，避免与 `nightMode:exit` 同帧空窗。
  - growth-wave：`clipPadding` 与烟雾外推量级对齐shader，放宽上限；viewer 计算 `far` 时用相机到场景中心欧氏距离替代纯前向投影，覆盖侧向／背向粒子。
  - Shader 自适应点大小：随归一化距离放大点尺寸，远近过渡平滑。
  - 事件顺序：`forceRenderNextFrame` 在抑制逻辑上仍能推进一帧，`frameend` 后清除，解除 LOD／非 LOD 的卡死路径。

### 6) View 资产显隐与标注、父级光源协议（4.28、4.27）

- **问题**：全量资产显隐需同步标注；reveal 播完前后标注易被错误隐藏／露出；光源需补齐元数据能力与父级托管一致性；Spot `rotate→move` 误写姿态；阴影方向改动因签名缓存未刷新。

- **方法**：
  - `ViewSettings.annotationsVisible` 为核心，facade 发 `assets:allVisibilityChanged`，标注监听；deferred reveal 解锁时按用户意图恢复标注。
  - 新增／扩展 `LIGHT_UPDATE`、`LIGHT_ADD` 名称、draft 区域落灯后触发与点击一致的 `placed`；点光配置类型字段；`LIGHT_COPY` 拷贝名、`LIGHT_BRUSH_RANGE_SET` 含点光、`SHADOW_DIRECTION_SET` 兼容字符串并清方向光签名缓存。
  - Spot 指针抬起仅在 `rotate` 且确有角度变化时回写欧拉，移除切模式时的兜底覆写。
  - 同日另有资产放置「预下载 + downloading/awaitingPlacement」两阶段光标与模块退出取消下载，与工作记录 **4.27**「资产 gaussian/mesh 未就绪点击异常」条目一致。

## 2026-04-20 ～ 2026-04-27

**区间**：`工作记录.md` **4.20、4.21、4.22、4.23、4.24、4.27**（4.25-4.26 无独立条目）。  
**方向**：相机导航稳定性与双击黑屏根治、聚光Gizmo万向锁修复、资产放置状态机、局部光照与Bloom观感优化、growth-wave大场景裁切。

*格式：问题 → 目标 → 方法；细节见工作记录。*

### 1) 相机导航稳定性与双击黑屏根治

- **问题**：偶发右键拖动后黑屏（NaN扩散）；双击场景后黑屏；相机初始位于包围盒外时步长过大、轻微操作即飞远；模式切换时相机瞬间吸附点位。
- **目标**：消除相机输入链路的NaN污染；双击聚焦稳定可靠；包围盒外导航手感正常；模式切换无跳变。
- **方法**：
  - `input-controller.ts` pan链路增加数值守护：对`width/height/dz`做有限值与下限保护，避免视锥切片计算产出NaN。
  - `update(dt, distance)`中将`distance`收敛为`safeDistance`，`orbitFactor`与`panMove`统一做finite校验；desktop move合成向量增加最终finite兜底。
  - `Camera.lerp`增加零向量/非有限值保护：当插值向量长度非有限或小于`CAMERA_LOOK_EPSILON`时保留已有姿态并钳制`distance`为正值，避免`1/distance`归一化产生角度NaN。
  - `orbit-controller.ts`的`onEnter`改为仅收敛`camera.distance`（按`zoomRange` clamp），**不再回算并改写`camera.position`**，规避单击/模式切换时的"瞬间吸附"跳变。
  - `camera-manager.ts`放宽orbit `maxZoom`上限系数（`0.5 -> 4.0`），避免包围盒外初始视角被过小上限强制拉近。

### 2) 聚光灯Gizmo旋转万向锁修复

- **问题**：Spot Light Rotate Gizmo绕X/Z轴旋转时pitch/yaw跳变、临界值翻转；万向锁导致操控手感异常。
- **目标**：基于PlayCanvas官方`RotateGizmo`实现稳定可靠的聚光灯旋转控制，无万向锁跳变。
- **方法**：
  - **轴启用策略**：禁用局部Y轴（roll轴），启用局部X和Z轴作为pitch控制候选，避免万向锁。
  - **coordSpace切换**：spot light rotate模式使用`local`坐标系，让Gizmo轴与锥体局部坐标系对齐。
  - **统一投影逻辑**：所有旋转轴统一使用照射方向（local -Y的世界方向）计算yaw，不再依赖各轴自身的方向向量。
  - **yaw连续性保持**：`getSpotYawFromDirection`在计算yaw时，选择最接近`fallbackYaw`的等价值（考虑±360偏移），避免atan2在0°/360°边界产生180°跳变。
  - **水平区域优化**：当|pitch|<15°（接近水平照射）时，直接使用`asin(垂直分量)`计算pitch，不依赖yaw，避免yaw误差导致的pitch突变到±180°。

### 3) 资产放置状态机与下载生命周期

- **问题**：资产放置时，如果gaussian/mesh未下载完成，用户点击场景会导致放置失败或异常；放置链路缺乏状态管理。
- **目标**：引入状态机管理下载/放置生命周期，放置流程可预期、可取消、有视觉反馈。
- **方法**：
  - `asset-facade.ts`新增`hydrateAssetForPlacement`方法，对gaussian/mesh类型资产在`ASSET_PLACE`命令时预下载，image类型保持原有异步加载方式。
  - 新增`handleAssetPlace`异步处理方法，将放置流程分为两阶段：
    - `downloading`：显示`wait`光标，禁用放置点击，后台下载资产。
    - `awaitingPlacement`：下载完成后切换为正常放置光标，允许用户点击场景放置。
  - `placement-cursor.ts`扩展`setPlacementCursorActive`接口，支持`loading`选项区分两种光标状态。
  - `onExit`中增加下载取消逻辑，切换模块时自动中断正在进行的下载，防止下载完成后误触发放置。
  - `asset-placement-handler.ts`简化`hydrateProtocolPlaceItem`，主下载链路已前移至facade层，handler仅做兜底兼容。

### 4) 局部光照与Bloom观感优化

- **问题**：局部灯`range`调大后gsplat核心亮区体感仍偏小，与mesh打光语义不一致；白光与彩色在低强度下主观亮度不一致；`bloomScope=global`时`LIGHT_TOGGLE_ALL`无法控制辉光开关。
- **目标**：让`range`同时影响截断边界与核心亮区覆盖半径；白光与彩色体感亮度一致；整灯闸控制完整覆盖。
- **方法**：
  - **range归一化衰减**：`night-mode.ts`将局部灯衰减从`1.15/(1+d^2)`改为`norm=dist/range, att=(1-norm)^2`（点光/聚光一致）；同步更新四套shader变体（GLSL主/GLSL BloomBrush/WGSL主/WGSL BloomBrush）。
  - **颜色能量整形**：`localLightLinearRgb`内新增**近中性色软压缩**（按线性空间色度估算`neutralWeight`，对白光/近白做温和降幅）与**感知等亮补偿**（基于Rec.709 luma权重对高饱和色做部分提亮），改善"同intensity下彩色显著更暗"的观感差异。
  - **Bloom整灯闸**：`environment-protocol-adapter.ts`的`applyLightToggleAll`增加Bloom scope分支；当`bloomScope === 'global'`时，将`LIGHT_TOGGLE_ALL`的`enabled`同步到`settings.postEffectSettings.bloom.enabled`，实现整场Bloom总闸开关。
  - **mesh与Bloom隔离**：`viewer.ts`改用PlayCanvas原生`camera.disablePostEffectsLayer`作为后处理截断机制，`local`时截断到`NoBloom`，`global`时恢复相机初始截断层。

### 5) growth-wave大场景裁切与相机优化

- **问题**：growth-wave大场景点云far裁切（cutoff），Phase2金色光圈只扫中心一小圈即结束；Phase1烟雾扰动项未封顶导致大场景下切向/径向/垂直扰动远超上限；相机farClip计算在斜视时远小于实际距离导致远景被裁成水平线。
- **目标**：让growth-wave在大场景下完整播放；Phase1/Phase2都有合理的空间范围；相机裁剪适应各种视角。
- **方法**：
  - `reveal.ts`：`endRadius`改为`max(50, revealEffect.radius, bbox外接球×1.05)`，保留JSON半径同时用大场景bbox保底。
  - `gsplat-growth-wave.ts`：Phase1对`maxScatterDistance`增加`min(..., max(uEndRadius, baseScatterDistance))`抑制径向倍数外推过远；新增`phase1NoiseCap = max(maxScatterDistance,1)×1.45`，对切向扰动、径向phase偏移、垂直扰动做`min`/`clamp`封顶。
  - `viewer.ts`的`farClip`改为`max(沿视轴估计, 欧氏距离+半径)+clipPadding`；再改为世界轴对齐AABB的视轴支撑`distFwd+|hx·fx|+|hy·fy|+|hz·fz|+padding`与球估计取大；带`nearMaxHint`时`near`改为仅`min(far/(1024*16), nearMax)`，避免yaw时摆动。
  - `getCameraClipHint()`抽象：将"特效对相机裁剪的影响"从viewer的`if (vfxType==='growth-wave')`分支，重构为脚本侧可选能力，`viewer.ts`仅消费该抽象。

### 6) 编辑输入链路与场景选中上报统一

- **问题**：编辑输入链路分散、多模块并发监听同一点击导致竞争；资产/光源/标注放置完成后场景选中上报语义不统一。
- **目标**：统一输入仲裁、消除竞争；放置完成后统一触发`SCENE_*_SELECTED`且来源为`scene`。
- **方法**：
  - 新增`input-arbiter.ts`，`viewer.ts`初始化接入；`input-controller.ts`在`pointerup`后先走可`claim`的点击分发，再决定是否继续广播通用事件。
  - `environment-facade`/`camera-manager`/`asset-placement-handler`/`annotation-toolbar/placement-mode`全量接入仲裁器并按优先级消费。
  - `asset-placement-handler.ts`：资产放置完成后`sceneAsset:selected`增加`{ source: 'scene' }`，再派发`sceneAsset:placed`。
  - `environment-facade.ts`：光源场景点击放置成功后，补发`sceneLight:selected { id, source:'scene' }`，与`sceneLight:placed`配对。
  - `annotation-manager.ts`：标注确认放置后默认选中改为`source:'scene'`，从而稳定触发`SCENE_ANNOTATION_SELECTED`。

### 7) 聚光角度语义与阴影稳定性

- **问题**：聚光灯角度语义 historically 混乱（整锥顶角vs半角）；环境模块高频调参时画面闪烁。
- **目标**：角度语义统一、可视化与实际受光一致；调参时不触发整屏重算。
- **方法**：
  - `settings.lighting.lights[*].inner/outerConeAngle`存库使用**整锥顶角（度）**，进入引擎前统一转换为PlayCanvas半角；转换函数重命名为`spotApexToHalfDeg`。
  - 默认值收口为：整锥顶角默认`inner=50`、`outer=90`（等效引擎半角约`25/45`）。
  - 移除历史自动迁移：`spotConeApexStorage`与`migrateSpotConeAnglesToApexStorage`下线，`ensureLighting`不再对旧settings自动×2迁移。
  - `updateSpotGizmoShape`优先读取`LightComponent`当前生效`inner/outerConeAngle`（半角）计算线框，避免配置值与运行时生效值偏差导致错位。
  - `updatePointLightsFromSettings`增加directional签名缓存，仅当方向光相关配置变化时才执行`applyDirectionalLightFromSettings`，降低局部灯高频更新触发整屏闪烁的概率。

## 2026-04-14 ～ 2026-04-18

**方向**：光源交互可视化、预览与编辑状态隔离、资产与标注交互稳定化、局部亮灯链路与暗部观感优化。

*格式：问题 → 目标 → 方法；细节见工作记录。*

### 1) 聚光灯和点光源可视化与交互

- **问题**：光源可视化大小和真实 `range` 有偏差，选中反馈不稳定；聚光灯旋转时手感不顺，容易出现角度控制不直观的问题。
- **目标**：让"看到的可视化范围"与"真实生效范围"一致；选中和拖拽反馈更稳；聚光灯旋转轴操作更符合直觉。
- **方法**：
  - 统一点光/聚光可视化半径计算规则，按引擎语义收敛到同一套参数口径。
  - 优化选中判定与屏幕空间兜底逻辑，减少"点不到、误选中"。
  - 调整聚光灯 Gizmo 的 yaw/pitch 约束方式，避免旋转过程卡顿或跳变。
  - 拖拽 Gizmo 命中时关闭相机抢输入，防止同帧既转相机又改光源。

### 2) 预览模式和编辑模式的 settings 状态隔离

- **问题**：预览态的临时开关会污染编辑态状态，模块来回切换后容易出现"设置漂移"。
- **目标**：预览态与编辑态各自维护独立状态；编辑始终以导入配置为基线，不受预览临时修改影响。
- **方法**：
  - 以 `previewMode` 作为单一真源，通过 selector 派生展示状态，避免多处布尔双写。
  - `PREVIEW_MODE_SET` 只负责状态更新，执行层统一从 selector 读取，不再各处自行分支。
  - 保留编辑基线快照，View 切回 Edit 时按基线恢复，确保"可编辑值"和"可比较值"一致。

### 3) 资产与标注选中交互优化

- **问题**：资产/标注选中链路里 id 语义不统一，偶发焦点双跳；Gizmo、拾取、相机控制会互相抢输入。
- **目标**：选中语义统一且可追踪；用户拖拽时不会误触其他交互；焦点移动稳定、可预期。
- **方法**：
  - 明确透传 `sceneEntityId`，统一 `ASSET_SELECT` 解析与触发条件。
  - 对列表点击与场景点击统一 frame/focus 触发策略，消除重复推镜头。
  - Gizmo capture 命中后暂停相机控制与资产拾取，交互结束再恢复。
  - 进入资产编辑时不再默认改选首项，减少"无感状态跳转"。

### 4) 局部亮灯区域优化

- **问题**：初始参数不对齐导致辉光不生效；实时涂抹阶段预览不稳定；暗部区域在局部提亮后仍有"黑、灰、脏"观感。
- **目标**：让初始参数开箱可用；实时涂抹"所见即所得"；预览与编辑参数互不污染；暗部提亮后观感更自然。
- **方法**：
  - 对齐 `intensity / threshold / blur` 默认参数口径，去掉历史映射与隐式夹值。
  - 将局部亮灯主链路切到体积投影 + shader 计算，减少 CPU 路径带来的颗粒与延迟。
  - 修复实时涂抹预览链路，补齐深度裁剪与提交态/预览态参数隔离，避免互相覆盖。
  - 在夜景路径加入暗部提亮与过曝抑制策略，兼顾"看得见细节"与"不过白"。

### 协议与消息通道

- **问题**：父级托管与本地 UI 易形成两套映射与两套默认。
- **目标**：入站事件统一落到 settings 真源；internal 与 message-bridge 行为一致。
- **方法**：
  - 以 **`message-bridge.ts`** 分发，**`environment-protocol-adapter.ts`** 承载环境 / Bloom / 光照 / 笔刷 / 阴影等写 settings + 场景；**`effects-protocol-adapter.ts`** 承载 VFX 等（与环境拆分）。

### 编辑壳层与选中回传

- **问题**：编辑 UI 与父级画布拆分后，选中与底部栏易脱节。
- **目标**：模块、右栏、底栏随 `EDIT_MODULE_SET` 切换；选中可回传父级。
- **方法**：`showEditUI` 总闸；`state` 驱动 Gizmo 与列表；`SCENE_*_SELECTED` / `SCENE_*_TRANSFORMED` 等出站。

### 场景拾取：资产 ID vs 深度世界点

- **问题**：全局一套 pick 时 gsplat ID 分支导致标注/笔刷拿不到深度与世界坐标。
- **目标**：资产 mesh 点选与「点场景取世界坐标」互不干扰。
- **方法**：**双 Picker**——资产 depth=false + 实例 ID；标注/笔刷/光源 depth=true + **`pickWorldFromClientXY`** 统一屏幕→世界。

### 局部亮灯多区域与 Bloom

- **问题**：单块笔刷无法表达多块独立亮区与父级托管 UI。
- **目标**：每区域独立 committed；体积与 Bloom mask 一份烘焙、多语义复用。
- **方法**：**`LocalLightRegion`** 列表 + active；仅 committed 持久化；**`bloomScope`** 分全局/局部；多区域亮度叠加 + 径向渐变 + 删空时 **1×1** 占位纹理防残留。
